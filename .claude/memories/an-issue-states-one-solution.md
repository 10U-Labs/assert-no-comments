# An issue states one solution

An issue names one change — this function, this file, this dependency. Never
file "either X or Y", a menu with a recommendation, or a question left for the
reader. Naming the alternative that lost is still worth writing; leaving the
choice open is not.

**Why:** the issue is the instruction to whoever picks it up, and they were not
in the conversation that produced it.

**How to apply:** settle the choice before filing, whatever form the issue
takes per [[issues-have-no-fixed-form]].
